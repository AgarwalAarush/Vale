# Vale
Vale is a general-purpose native macOS companion. Learning is an optional mode. Preserve legacy Lilt storage and bundle identifiers. The assistant persona is not renamed by product branding. On 2026-10-20 the owner clarified the product: a keyboard-shortcut summoned top-right floating panel, approximately 300×45pt at rest, expanding in place for typed/spoken questions, current-work and explicit file/window context and replies. The large history-sidebar workspace is rejected. One assistant panel replaces both the earlier detached capsule/coach pair and the large workspace. Preserve capabilities through on-demand routes. The current compact design exploration is docs/design/compact-companion-2026-10-20/README.md; the owner approved 01-pearl-glass.png on 2026-10-20. Build that Pearl topology, not the previously recommended Lens; the comp is a design reference, never runtime evidence.

Build: `scripts/build.sh`. Core tests: `swift run --disable-sandbox LiltCoreChecks`. Native UI checks: `scripts/verify.sh` (added with app harness). Render and inspect screenshots of the actual AppKit/SwiftUI views, not a browser reconstruction.

Never log credentials, selected text, microphone audio, or screenshots. No automatic selected-window choice, startup capture/microphone activation, paid fallback, or launch-on-login registration. Publishing source or binaries requires an explicit user request. Store sessions atomically and preserve drafts. Every async completion must validate its session and request identity. Screen context must be refreshed at request time. Only explicitly enabled web search may be exposed to the model; no command, file, app, or browser tools. Uploaded files are deliberately retained with chats; captured screenshots, selected text and microphone audio are not.

The owner's latest automatic current-work context defaults on and can be disabled. Before explicit invocation activates Vale, remember the non-Vale source app/display and read only its AXSelectedText; refresh selection and capture a fresh current-display screenshot, excluding Vale, only for an explicit question. Keep selection bounded to16000 UTF-16 units and screenshots at most1600px on the long edge, transient in RAM/current provider input; never append raw context to saved user questions or retain it as attachments. Explicitly selected-window context takes screenshot precedence. Screen Recording and Accessibility prompts require explicit user actions; denial must leave typing available. No background screen/selection polling, simulated clipboard Copy to read selection, startup capture or model tools. Disable, pause/hide, sleep/lock and session changes clear transient buffers and invalidate pending work. Control–Option–Space shows/focuses or hides Vale; Control–Option–D explicitly toggles dictation with visible status/Stop.

Selected-window Live context is explicit opt-in on one selected window, refreshed locally with one bounded RAM preview; send only on a question/guide action. Conversation may rearm the microphone only after explicit opt-in and the current playback completes. Pause, Escape, sleep/lock, session changes and errors stop it. Do not call this full-duplex or network streaming. Forget must purge target content from the legacy backup and report deletion failures with retryable state. Synthetic capture/voice tests must stay labeled and never imply real hardware consent coverage.

For native UI work, follow docs/design/native-product-pipeline.md with the latest owner brief taking precedence over its historical large-window geometry. The owner rejected the large-window product direction; earlier visual approval is reopened.
